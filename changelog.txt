*** CartShift – OpenCart to WooCommerce Migration Changelog ***

2026-05-31 - version 2.5.68
* Added - 'wp octowoo fix_term_language' CLI command to repair terms that the multilingual pass mislabeled as the secondary language. Finds secondary-flagged terms whose name has no secondary-language (Arabic) characters and that have no primary-language twin, and flips their WPML language_code back to primary (each becomes a standalone primary-language term on its own trid). Nothing is deleted and no products move — this RESTORES mislabeled English categories rather than removing them. Dry-run by default.

2026-05-31 - version 2.5.67
* Fixed - fix_slugs merge now counts and moves ACTUAL term_relationships rows instead of trusting the cached tt.count (which is stale/0 under WPML), so products on a duplicate are never orphaned when it is deleted. Dry-run now reports the real number of links that will move.
* Added - WPML language guard: a ow-t- duplicate is only merged into an original of the SAME language. If the duplicate and candidate original are in different languages, the merge is SKIPPED and flagged for manual review — preventing Arabic products from being attached to an English category term.

2026-05-31 - version 2.5.66
* Fixed - ow-t- slug cleanup was about to produce percent-encoded slugs (e.g. %d8%a7%d9%84...) because both the Full Cleanup button and fix_slugs used sanitize_title(), which URL-encodes Arabic. Both now use the Arabic-preserving slug format (matching AbstractMigrator::toSlug), keeping readable Arabic URLs.
* Fixed - fix_slugs now correctly treats ow-t- terms that duplicate an existing clean-named term as DUPLICATES: it merges their products into the original and deletes the stub, instead of merely renaming the duplicate's slug (which left the duplicate alive). Only genuinely unique ow-t- terms get an in-place slug repair. SEO of the original term is preserved.

2026-05-31 - version 2.5.65
* Fixed - "Full Cleanup" admin button failed ("request failed") on large catalogs because the handler lacked an execution-time/memory raise that every other heavy handler in the class already has. Added set_time_limit(0) + 512M like the others.
* Added - 'wp octowoo fix_slugs' CLI command — repairs leftover 'ow-t-…' temporary term slugs back to clean slugs from the term name, in the terminal with no web timeout. Dry-run by default; skips collisions. Use --apply to write.

2026-05-31 - version 2.5.64
* Added - 'wp octowoo audit_translations' CLI command to diagnose and clean orphan secondary-language (Arabic) term stubs — the cause of Arabic showing far more terms than English (e.g. product_cat Arabic 287 vs English 96). Finds secondary-language terms whose translation group has no primary-language parent AND that carry no products, shows counts + a sample, and (with --apply) removes only those orphan stubs. Terms with products are never touched. Dry-run by default.

2026-05-31 - version 2.5.63
* Fixed - dedupe_terms is now strictly safe. It groups by name AND slug together, so only genuine duplicates (identical name + identical slug) are merged. Any group where a slug is shared across different brand/category names — i.e. scrambled data from an earlier bad run — is SKIPPED and reported for manual review rather than auto-merged, preventing accidental merging of distinct brands. Removed the slug-transfer step (members already share a slug) and fixed the keeper recount.

2026-05-31 - version 2.5.62
* Fixed - Root-cause idempotency fix for duplicate brands/categories on re-run. Brand lookup now matches existing terms by name across ALL languages via a direct query (get_term_by only saw the current WPML language, so re-runs created duplicates). Category name-fallback now matches an existing term under ANY parent even when a parent is set, preventing duplicate 'ow-t-…' category stubs on WPML re-runs. Re-running the migration now reuses existing terms instead of multiplying them.
* Added - 'wp octowoo dedupe_terms' CLI command to clean up existing duplicate categories/brands safely and WITHOUT SEO loss. Dry-run by default; keeps the populated term (highest product count), reassigns any product links to the keeper, transfers a clean slug to the keeper when the duplicate held it (so existing URLs/redirects survive), cleans up WPML icl_translations rows, and removes only the empty duplicates. Use --apply to execute, --taxonomy to scope.

2026-05-31 - version 2.5.61
* Cleanup - Removed the temporary timing instrumentation now that the multilingual tag bottleneck is fixed (confirmed ~130s/product → ~0.5s/product). Product log lines keep the SKU + name for readability; the verbose timing(ms)/breakdown lines are gone. No behavior change.


2026-05-31 - version 2.5.60
* Fixed - Made the product-tag path fully direct-DB. wp_insert_term() and get_term_by() were replaced with direct wp_terms/wp_term_taxonomy find-or-create and direct lookups, so WPML's created_term re-sync (the residual ~90s when taxonomies are out of sync) no longer fires. Combined with the v2.5.59 direct icl_translations linking, the entire tag section now touches the database directly with zero WPML hooks. Added a one-line tag-loop timing breakdown (findOrCreate vs link) so the result is verifiable.


2026-05-31 - version 2.5.59
* Fixed - THE multilingual speed fix. Confirmed via timing logs that ~90s/product was spent in the product-tag section, where each tag fired up to three wpml_set_element_language_details actions — each triggering WPML's full taxonomy re-sync (~2s) because taxonomies were flagged out of sync. Replaced those WPML hook calls with direct, indexed icl_translations writes (INSERT … ON DUPLICATE KEY UPDATE). The English tag row is only created if missing, never overwritten, so English terms never drop from their language filter. Tag time drops from ~90s to a few milliseconds, which also resolves the "stops after 2-3 products" stalls (chunks now finish within the time limit and schedule the next one).


2026-05-31 - version 2.5.58
* Diagnostic - Added sub-timing inside copyProductDataToTranslation() (meta/type/cat/tag/brand) — confirmed via v2.5.57 logs to be the sole bottleneck (~130s/product). Logs a breakdown line whenever copy() exceeds 3s, pinpointing the exact slow taxonomy section before the targeted fix.


2026-05-31 - version 2.5.57

2026-05-31 - version 2.5.56

2026-05-31 - version 2.5.55
* Performance - Eliminated the multi-minute stall at the start of every multilingual chunk. The untranslated-product count and fetch queries no longer compare the unindexed LONGTEXT postmeta.meta_value to a post ID (a full scan that got slower with every translation created). They now use indexed (post_id, meta_key) lookups via a new '_octowoo_has_translation' flag set on each translated English product, plus a one-time idempotent backfill for products translated before the upgrade. The fetch also now correctly excludes the Arabic posts themselves. Combined with v2.5.53, each chunk should complete in seconds instead of timing out after ~3 products.

2026-05-31 - version 2.5.54

Fixes products that show an empty thumbnail even though the image already exists in the media library. Use --dry-run to preview, --download for an optional slow remote fallback.

2026-05-31 - version 2.5.53
